# Validated Data Pipeline and Analytics Model

## Chosen dataset

`data/raw/workforce_snapshot_sample.csv` is a synthetic, non-personal workforce planning snapshot created for this project. It intentionally contains common source-format variation (case, whitespace, date formats, currency notation) while preserving no real employee data. In production it is replaced by an access-controlled HRIS extract with the identical contract.

Run the complete build from the repository root:

```sh
python3 src/pipeline.py
python3 -m unittest discover -s tests -v
```

The pipeline never overwrites raw input. It writes a conformed CSV to `data/staging/workforce_snapshot_clean.csv`, creates a disposable local SQLite database at `data/workforce_lens.db`, and regenerates `reports/data_quality_report.md`. Database and staging data are ignored by Git; only the safe synthetic raw sample and generated report are versioned.

## Transformation ledger

| Input field | Transformation | Output / rule |
| --- | --- | --- |
| all text | trim whitespace | Empty text becomes null where permitted. |
| identifiers | trim and uppercase | `worker_id`, organization and location business keys are canonical. |
| labels/categories | trim, case-fold and map | Organization, location and job-family labels use title case; statuses are `ACTIVE`, `LEAVE`, `TERMINATED`; termination types are uppercase. |
| dates | parse `%Y-%m-%d`, `%m/%d/%Y`, or `%Y/%m/%d` | ISO-8601 date output. |
| FTE/hours/units | decimal parse | Numeric output; range validations apply before load. |
| labor cost | remove currency symbols/commas and parse | `labor_cost_inr` decimal, with `currency=INR` required. |
| source entities | de-duplicate dimension values | Deterministic surrogate keys generated by sorted business key. |

## Star model

`stg_workforce_snapshot` is the clean landing table at the same source grain. `fact_workforce_snapshot` has explicit grain of **one worker business key, one snapshot date, and one scenario**. It retains the pseudonymous `worker_id` as a degenerate business key; it is not published to consumer reporting. Its foreign keys reference `dim_date`, `dim_organization`, `dim_location`, `dim_job_family`, and `dim_scenario`. Surrogate keys are integer keys produced during load; business keys remain canonical source identifiers.

## Quality controls

The pipeline blocks a load on missing columns, required-field nulls above zero, duplicate grain, invalid ranges, invalid category values, invalid dates, unsupported currency, stale snapshots (more than 45 days before the run date), or row-count/labor-cost reconciliation failures. After the database load it checks foreign-key integrity with `PRAGMA foreign_key_check`. The report records checks, thresholds, actuals, source/stage row counts, source/stage labor-cost totals, and freshness.
